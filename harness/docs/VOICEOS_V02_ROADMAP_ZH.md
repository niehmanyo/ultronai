# VoiceOS V0.2 — Siri 式免按键、快速且可靠的连续语音对话

## 产品定义

**目标：** 用户启动 Ultron 后，不必按回车，正常说话即可形成一轮请求；Ultron 在用户自然说完后，尽快给出准确、有依据的回应，播报完自动恢复监听。

**明确不做：** 语音打断（barge-in）、边播报边收取新问题、对当前任务的抢占、电影原声模仿、先做 UI。V0.2 的播放和采集是严格串行的，Ultron 播报时不接收新一轮语音。旧的 `--barge-in` 命令已删除。

**保留：** 已验收的 DeepSeek Harness SDK + OpenAI adapter、独立 Session 多轮上下文、英文 GLACIAL 原创 TTS、中文/英文提问、中文提问英文回复开关、macOS 推送录音模式作为回退。

## 用户体验及状态机

`IDLE/LISTENING → SPEECH_DETECTED → END_OF_TURN → TRANSCRIBING → ROUTING → AGENT_WORKING → SPEAKING → LISTENING`

- 启动一次持续监听，按 Ctrl+C 正常退出；不需要按 Enter 或每轮重新启动。
- 检测到讲话显示 Listening/Speech detected；自动识别说话结束并转写；长停顿不能频繁截断一句话。
- 产生一条完整用户消息后才调用 DSH Agent；保持同一运行时 Session ID。
- Agent 回复时系统暂不监听，避免 TTS 自我回声触发；播报结束再监听。
- 复杂任务耗时较久时可用 UI/终端提示状态，不得用“我已经查证”这类不实占位语音冒充结论。

## 技术方案与阶段验收

### P0：移除打断、稳定免按键（本次代码清理）

- 删除 `--barge-in` CLI、TTS/VAD 的播放监控分支和相关单元测试。
- 默认兼容 `python voiceos/core.py` 推送录音；免按键明确使用 `--hands-free`。
- 实机测试：10 次自然语音问答、20 次 0.3–1.5 秒停顿；无回车、无麦克风卡死，播报结束回到监听。
- 审查 PR #4 的差异，确认不再包含相关源码；文档中历史阶段说明仅供追溯。

### P1：自动断句（最优先）

- 当前 RMS VAD 是本地能量门限，默认 240ms 起音、750ms 静音结束。优点为轻量、低成本；缺点为背景噪声/句中停顿误切。
- 首先记录 VAD 语音起点、终点、误触发/误切分、以及录音空白；调节 `--vad-threshold`、静音尾时长、最大句长，并明确输出设备选择。
- 增加完整 speech VAD（例如本地神经 VAD）或者独立 Realtime transcription 的 server_vad/semantic_vad；取舍须验证目标模型对自动断句的支持及成本。OpenAI 官方 `server_vad` 可以通过静音时间调节响应速度，`semantic_vad` 可以根据表达是否结束延长或缩短等候；后者未必延迟更低。
- 开发条件：能在 Mac 网络及代理环境稳定使用 API；不能随便把 `gpt-realtime-whisper` 当作自带 VAD。
- 验收：发话后无需回车 100% 完成各类预设测试用例；安静/一般噪声环境分别观察“漏检、误切、迟滞”，没有数据前不作绝对承诺。

### P2：降低响应延迟（不牺牲正确率）

- 为每轮建立本地 Timeline：录音结束/ASR 请求/ASR 完成/Agent 开始/首有效 token/Agent 完成/TTS 请求/首音频/TTS 完成/播放完成；输出 P50/P95。
- **先做易得优化：** SDK 进程与会话常驻；复用 OpenAI client；限制无意义重试；合理的语音段长度；避免每轮重复初始化；有条件时做文本/声音缓存（只缓存严格可复用内容）。
- **其次研究流式接口：** 官方 SDK 若支持可靠的 token/消息增量事件，就使用完整句缓冲分句 TTS；否则在能验证的 SDK 接口基础上迭代，禁止凭空假设 API；TTS 用真实的流式音频传输，而非把下载完的 WAV 称作 streaming。
- 增量播放与准确率隔离：只有稳定成句、无工具副作用且不会被后续证据推翻的内容才提前播报；事实性结论、计算结果与工具执行结果必须核验后才读出来。
- 优先追求首次有效答复 P50 < 3 秒（简单任务、合理网络环境的**初始目标**）；复杂任务则关注状态透明度与最终正确性，不能保证都在 3 秒内完成。

### P3：保证回答质量（路由 + 验证）

- 保持 DSH Agent 作为唯一执行/推理内核，语音层只负责 VAD、ASR、TTS、用户确认，不重新发明业务 Agent。
- 任务按成本与风险分级：A=寒暄/简单命令直接回应；B=一般知识与项目问答由 DSH 正常推理；C=查证、代码、计算、最新信息和有副作用的动作需要真实工具和结果验证/必要时用户审批。
- 不自动在弱模型上处理复杂任务；可按证据/错误/工具结果回退至较强模型或延长处理，不凭自评置信度声称正确。
- 对语音识别不确定的关键参数（路径、金额、日期、联系人、删除动作等）先读回确认，再执行；不能做危险操作的默认授权。
- 建立覆盖率题集（至少 60 条）：简单 20、中等 20、需要工具/验证 20。存储标准答案、预期工具、来源/通过规则、失败类型、时延。逐版本比较 pass rate 和成本，发现准确率回归即不扩大部署。
- “准确率高”是**在题集上量化改进**，不是绝对正确承诺；对于不了解的事实应承认不知道。

### P4：Siri 式可用性/可靠性

- 麦克风独占与权限检测、自动恢复音频设备断开/重连、连续听讲时隐藏系统错误恢复、Ctrl+C 正常释放设备。
- 调试模式输出状态机与时延；默认不记录原始音频或明文隐私文本；安全处理 API keys。
- 退出条件和闲置超时可配置；设备不支持 16kHz 时选择设备默认采样率并规范重采样。
- 未来可选唤醒词“Ultron”，但**本次不把唤醒词作为不按回车的前置条件**。

## 优先级与交付节奏

| 次序 | 交付 | 验收重点 |
| --- | --- | --- |
| 0 | 删除打断、稳定顺序对话 | 无回车连续沟通；不再运行打断监控 |
| 1 | VAD 断句可靠性与可调参数 | 短暂停顿不断句，停语后快速提交 |
| 2 | 延迟 Timeline 和请求复用 | 准确测量第一句等待、P50/P95 |
| 3 | Agent 路由、质量校验及题集 | 提升可复现任务正确率，避免错误提前播报 |
| 4 | 验证真正流式 TTS/DSH | 缩短首声音延迟，不误播未核实结论 |
| 5 | 全链路长时间稳定性和断线恢复 | Mac 连续运行测试、无回车、多轮上下文 |

## 操作与回退

```bash
cd ~/Downloads/ultron-web
git fetch origin
git switch feature/voiceos-v02-streaming
git pull --ff-only origin feature/voiceos-v02-streaming
cd harness
source .venv-voiceos312/bin/activate
python -m unittest discover -s voiceos/tests -v

# 当前自动对话模式：无回车
python -u voiceos/core.py --hands-free --tts openai --persona glacial --reply-language en --robotic 55

# 退回默认的按键录音模式
python -u voiceos/core.py
```
